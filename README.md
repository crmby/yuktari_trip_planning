# Планирование выездов · Юктари

Приложение для работы внутри Битрикс24 VibeCode. Текущий этап — структура, окружение и подготовка доставки. Планирование и интеграция с CRM ещё не реализованы.

## Быстрый запуск

Нужен Node.js 20.12+; для локальной разработки рекомендуется Node.js 24 LTS.

```powershell
npm ci
Copy-Item .env.example .env # только если .env ещё не создан
npm run dev
```

Откройте http://127.0.0.1:3000. Локальный `.env` уже создан с пустыми полями интеграции. Не заменяйте заполненный `.env` примером. Зависимостей сторонних пакетов на этом этапе нет.

```powershell
npm run check
npm test
npm run deploy:check
```

Последняя команда проверяет архив `deploy-preview.tar.gz` без чтения `.env` и без сетевых запросов. PHP-шаблон не запускается этими проверками.

## Структура

| Каталог | Назначение |
|---|---|
| `src/` | HTTP-сервер, конфигурация и маршруты |
| `public/` | Стартовый экран, стили Air и подгонка iframe |
| `scripts/` | Проверка синтаксиса, упаковка и деплой |
| `tests/` | Проверки конфигурации и границ HTTP-доступа |
| `docs/` | Назначение и настройка VibeCode |
| `memory/` | Состояние и принятые решения |
| `.agents/skills/bitrix24-apps/` | Приложенный скилл, установленный для этого проекта |
| `templates/b24-advanced-php/` | Исходный PHP-комплект из архива без изменений |

PHP-шаблон использует классические OAuth-сессии и BX24 SDK. Для VibeCode подготовлен отдельный Node.js-каркас по образцу SyncPoint: так механизмы авторизации двух сред не смешиваются. Стили взяты из приложенного скилла. PHP-комплект служит источником компонентов и решений, в архив деплоя не попадает.

## Деплой

Порядок — [docs/DEPLOY.md](docs/DEPLOY.md). После настройки существующего сервера и локального `.env`:

```powershell
git pull --ff-only
npm ci
npm run check
npm test
npm run deploy
```

`npm run deploy` отправляет локальную рабочую копию на VibeCode; сам GitHub он не скачивает и Git-команды не выполняет. На машине, с которой выполняется доставка, сначала нужно подтянуть нужный коммит. Автодеплой по push не настроен.

`/health` отдаёт состояние процесса. Доступен только общедоступный каркас без данных портала. Все `/api/*` отвечают `503 INTEGRATION_NOT_CONFIGURED`. До подключения CRM необходимо реализовать проверку сессии сотрудника VibeCode и согласовать роли.

## Git

Целевой remote: https://github.com/crmby/yuktari_trip_planning.git, ветка `main`.
Аккаунту `vrodionova-eng` предоставлен доступ; первая отправка в GitHub выполнена успешно. Локальная ветка `main` отслеживает `origin/main`. Владельцем репозитория остаётся `crmby`. Для дальнейшей синхронизации используйте `git pull --ff-only` и `git push`. Не используйте force push.

Скилл установлен в `.agents/skills` и будет доступен при следующем обращении в этом проекте.
