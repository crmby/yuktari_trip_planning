# Планирование выездов · Юктари

Версия 0.3: приложение Node.js для Битрикс24 VibeCode. Реализованы маршрутный лист, запись из сделки, мастера и графики, серверное резервирование и синхронизация согласованных полей контакта и сделки. Wialon не подключается; его идентификатор хранится только для будущего сопоставления.

## Запуск и проверки

Требуется Node.js 20.12+. Сторонних зависимостей нет.

```powershell
npm ci
# Копировать только при отсутствии .env: Copy-Item .env.example .env
npm run dev
```

Открыть http://127.0.0.1:3000. Не заменяйте заполненный `.env` примером. Секреты нельзя добавлять в Git или чат.

- `APP_MODE=demo`: вымышленные данные, сохранение в браузере, дата 25.11.2026. Описание — [docs/DEMO.md](docs/DEMO.md).
- `APP_MODE=bitrix`: общие данные приложения на сервере, CRM через проверенную сессию сотрудника VibeCode. Без сессии данные закрыты; локальный прямой вход в CRM не предусмотрен.
- Без APP_MODE наличие VIBE_APP_KEY выбирает bitrix, иначе demo. В `.env.example` явно включено demo.

```powershell
npm run check
npm test
npm run deploy:check
```

Последняя команда создаёт `deploy-preview.tar.gz` без чтения `.env`, сети и выкладки. Проверки интеграции используют вымышленные ответы API. Работа на портале требует отдельной приёмки после ручного деплоя.

## Подключение Битрикс24

Настройка OAuth-приложения, переменных окружения, вкладки сделки и приёмка — [docs/CRM.md](docs/CRM.md). Точные поля — [docs/FIELD-MAP.md](docs/FIELD-MAP.md). Ручной деплой — [docs/MANUAL-DEPLOY.md](docs/MANUAL-DEPLOY.md).

Где взять каждую переменную — [docs/ENVIRONMENT.md](docs/ENVIRONMENT.md). Команда `npm run app:check` проверяет принадлежность локального OAuth-ключа порталу и приложению с нужным адресом, без изменения настроек.

Из вкладки сделки текущая сделка подставляется автоматически. В отдельном приложении доступен поиск по названию или ID. Ограничений по воронкам нет; действуют права сотрудника в CRM. При сохранении обновляются три поля контакта и шесть полей сделки; услуги читаются из всех товарных позиций. Стадии, товарные позиции и Wialon приложение не меняет.

Перед CRM-записью сервер проверяет актуальность данных и свободное время мастера, сохраняет резерв, затем проверяет результат чтением из CRM. При неизвестном результате резерв остаётся; повторная запись автоматически не выполняется. Общие данные находятся вне public в DATA_DIR; при ручном деплое нужно сохранить этот каталог.

## Структура

| Каталог | Назначение |
|---|---|
| src/bitrix/ | Проверка сессии, CRM, резервирование, приватное хранилище |
| public/ | Интерфейс Air, расписание и демонстрационная модель |
| scripts/ | Проверки, упаковка, ручной деплой |
| tests/ | Правила планирования и интеграционные проверки с тестовым API |
| docs/ | Настройка, поля, ограничения и приёмка |
| memory/ | Состояние проекта |
| templates/b24-advanced-php/ | Справочный PHP-комплект, не запускается и не попадает в деплой |

## Git и доставка

Репозиторий: https://github.com/crmby/yuktari_trip_planning.git, владелец crmby. Основная ветка main отслеживает origin/main. Аккаунту vrodionova-eng предоставлен доступ. Удалённую историю не переписывать.

`npm run deploy` доставляет текущую локальную копию на существующий сервер, сам GitHub не скачивает. Обёртки: `./deploy.ps1` и `bash ./deploy.sh`; для проверки архива — `-DryRun` / `--dry-run`. Перед реальной доставкой обновите код через `git pull --ff-only`. Автодеплой по push не включён. Реальный деплой этой версии агент не выполнял.
