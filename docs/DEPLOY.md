# Окружение и доставка в VibeCode

Подробные параметры ручной доставки — [MANUAL-DEPLOY.md](MANUAL-DEPLOY.md), подключение CRM — [CRM.md](CRM.md).

npm run deploy упаковывает src/, public/ и два package-файла и отправляет multipart в POST /v1/infra/servers/{SERVER_ID}/deploy?stream=false. Скрипт использует Node.js и tar; одинаковый код запускается через deploy.ps1 и deploy.sh. npm run deploy:check выполняет только упаковку, без чтения .env и без сети.

Перед реальной доставкой нужны SERVER_ID, VIBE_API_KEY и B24_DOMAIN. Проверяются /me и режим существующего сервера BLACKHOLE. Для рабочего режима также нужны APP_MODE=bitrix, VIBE_APP_KEY и APP_URL. Ключ управления используется только для доставки. Ключ приложения и разрешённые настройки передаются в серверную среду; ни один ключ не включается в архив и не выводится в журнал.

Настройки: runtime node20, npm ci --omit=dev, node src/server.js, порт 3000, cleanDeploy=true. Постоянное хранилище объявлено через dataDirs=["/opt/data/yuktari-trip-planning"], runtime DATA_DIR указывает туда же. Скрипт не создаёт сервер и не меняет режим доступа. Реальная доставка может расходовать Вайбы и обновить видимую сотрудникам карточку приложения — пользователь выполняет её самостоятельно.

Перед выпуском: git pull --ff-only, npm ci, npm run check, npm test, npm run deploy:check; сохранить прежнюю сборку, настройки и приватную базу. После выпуска проверить журнал, вход, права, iframe и тестовую синхронизацию. Успешный ответ доставки не заменяет приёмку внутри портала.

Вкладка регистрируется отдельно из приложения после входа администратора. Для изменения высоты iframe используется vibe:resize; при необходимости включить placementResizeEnabled в настройках встраивания VibeCode. BX24 SDK в техническом обработчике VibeCode не используется.

Предыдущие попытки проверки API с этой машины завершались DNS/TLS-таймаутом до проверки ключа. Поэтому актуальные ключи, режим и совместимость целевого сервера не подтверждены. В текущем этапе реальная доставка не запускалась.

Источники: [runtime](https://vibecode.bitrix24.tech/docs/infra/app-runtime), [постоянные каталоги при деплое](https://vibecode.bitrix24.tech/docs/changelog/2026-08-11).

## Источники переменных и видимость каталога

Полный список, где взять каждую переменную: [ENVIRONMENT.md](ENVIRONMENT.md). Добавлена npm run app:check для сверки локального OAuth-ключа, портала и адресов без пользовательской сессии. Не путать эту проверку с проверкой ключа в runtime или сессии сотрудника.

Перед отправкой скрипт читает GET /infra/servers/{id}, сохраняет прежние настройки видимости и спрашивает о карточке/чате только при NOT_CHOSEN и itemId=null. При обновлении передаёт displayName, description и changelog (можно задать DEPLOY_CHANGELOG). После доставки перечитывает сервер и сообщает фактическое состояние каталога. Доступ, права, гостевые ссылки и режим сервера не меняются.

26.11.2026 пользователь явно разрешил реальную доставку на существующий сервер. Обязательный предварительный GET из среды агента завершился UND_ERR_CONNECT_TIMEOUT до HTTP-ответа. POST deploy не выполнялся; состояние каталога неизвестно. Пользователь сообщил, что доставка из её терминала работает.

## Явный источник ключа доставки

Для подтверждённого пользователем сервера Юктари использовать npm run deploy -- --key-source=app: сервер связан с OAuth-ключом VIBE_APP_KEY, а не с личным VIBE_API_KEY. Предварительная проверка: npm run app:check -- --key-source=app. Параметр задаёт источник до первого запроса, не является автоматической сменой ключа после 404. При отказе GET сервер не разворачивается. Инфраструктурным GET/POST deploy достаточно управляющего ключа с vibe:infra без Bearer; сессия всё ещё нужна для CRM. Подробности — ENVIRONMENT.md.
