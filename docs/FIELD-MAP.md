# Карта полей перед подключением CRM

В текущем этапе используются только тестовые данные. Реальные коды полей, ID воронок, значения списка маршрутов и стадии не определены: они должны быть получены из портала после настройки авторизации. Wialon в эту карту не входит.

| Значение | Поле демо | Источник в боевой версии / статус |
|---|---|---|
| Сделка | dealId | ID существующей сделки; проверять права пользователя |
| Воронка | deal.funnel | CATEGORY_ID; сопоставить четыре названия из ТЗ с фактическими ID |
| Клиент и контакт | deal.client, deal.phone | Связанные компания/контакты, учитывать несколько телефонов |
| Адрес и город | address, city | Сверить поля сделки и формат CRM-адреса |
| Область и район | region, district | Определить UF-поля, типы и обязательность |
| Квартира | apartment | Отдельное текстовое UF-поле |
| Координаты | lat, lon | Согласовать CRM-хранение и источник геокодирования |
| Маршрут | route | UF-поле типа «Список», загрузить реальные ID/подписи вариантов |
| Дата обслуживания | date | UF-поле даты |
| Окно приезда | windowStart, windowEnd | Два поля времени или согласованный формат; хранить раздельно |
| Плановая длительность | duration | Отдельное числовое UF-поле, минуты |
| Позиция строки | position | Отдельное поле приложения/сделки, не подменяет клиентское окно |
| Резерв мастера | masterId, actualStart | Запись в общей базе приложения; согласовать отображение в CRM |
| Возраст системы | years | Заполняется менеджером, определить UF-поле |
| Услуги | deal.products, deal.service | Все товарные позиции: имена, цены, полный перечень; определить UF-поле «Услуга» |
| Комментарий | comment | Согласованное поле комментария, отдельно от клиентского окна |
| Выполнение | status | Определить доступный источник в сделке; пока ручной тестовый статус |
| Стадия при записи | deal.demoStage | «Время назначено»; фактический STAGE_ID не настроен |
| Стадия при отмене | deal.demoStage | «Пересогласовать время»; уточнить расхождение названий стадий в ТЗ |

Перед реальными записями: заполнить для каждой из четырёх воронок фактические коды, проверить тип/обязательность/права, утвердить алгоритм доступности и серверную транзакцию. Только после этого включать сохранение в CRM и обработку изменений сделок.
