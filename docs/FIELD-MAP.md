# Карта полей CRM

Коды предоставлены пользователем для yuktari.bitrix24.by. Имена для запросов VibeCode берутся из доступной схемы `/deals/fields` и `/contacts/fields`, а не вычисляются вслепую. Недоступное поле блокирует сохранение.

| Значение | Владелец | Поле |
|---|---|---|
| Адрес обслуживания | Контакт | UF_CRM_1795682518 |
| Квартира / офис | Контакт | UF_CRM_1532084146058 |
| Маршрут | Контакт | UF_CRM_1619006158 |
| Дата обслуживания | Сделка | UF_CRM_1612779971491 |
| Интервал приезда с | Сделка | UF_CRM_1795682623 |
| Интервал приезда до | Сделка | UF_CRM_1795682642 |
| Плановая длительность, минуты | Сделка | UF_CRM_1795679140 |
| Комментарий клиента | Сделка | UF_CRM_1795682687 |
| Сколько лет системе | Сделка | UF_CRM_1795682809 |

Окно приезда и комментарий хранятся отдельными значениями. Возраст системы подставляется из сделки и может быть изменён менеджером. Адрес, квартира и маршрут читаются и записываются в основной контакт сделки. При отсутствии однозначного основного контакта запись запрещается.

Маршруты — элементы инфоблока, связанного с UF_CRM_1619006158. ID инфоблока определяется по metadata пользовательского поля. При необходимости ID можно явно задать через B24_ROUTE_IBLOCK_ID. Фактический тип читается через GET /lists/{id}/type; B24_ROUTE_IBLOCK_TYPE больше не применяется. Элементы загружаются со всеми страницами без серверного фильтра ACTIVE; возвращённые элементы с ACTIVE=N исключаются. В CRM сохраняются ID, в интерфейсе показываются названия.

Услуги — все товарные позиции сделки: название, количество и цена. Доступны только для чтения, отдельное поле услуги не создаётся. Телефон — основной телефон контакта. Колонка «Выполнение» показывает успешное завершение сделки по stageSemanticId=S, иначе «В работе»; отдельное поле выполнения пользователь не указал.

Маршрутный лист показывает время/номер строки, возраст системы, маршрут, адрес с квартирой, телефон, услуги, окно и комментарий, выполнение. Над листом — дата и название маршрута. Город, область, координаты, ручной статус и особая отметка убраны из формы выезда.

ID приложения мастера, ID сотрудника Битрикс24, активность, направления, группы, необязательный Wialon ID, неделя и исключения графика хранятся в общей базе приложения. ФИО берётся из подтверждённой записи сотрудника. Сотрудников приложение не изменяет. Направления используют тот же справочник маршрутов.

Фильтр, поиск и календарь используют только ID 6, 0, 8 и 10: обслуживание юридических лиц, обслуживание физических лиц, продажа/аренда и безвозмездное пользование. Названия читаются из /categories/2, сопоставление идёт по ID. Открытие из вкладки сделки по-прежнему проверяет доступ через CRM, без запрета по тексту названия. Тип клиента определяется по наличию связанной компании, а не по названию воронки. Стадии, товары, роботы и Wialon не меняются. Изменение пользовательских полей может запускать уже настроенные в портале автоматизации — это нужно проверить на тестовой сделке при приёмке.
