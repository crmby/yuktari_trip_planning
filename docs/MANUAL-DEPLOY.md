# Ручная доставка тестовой версии 0.2

## Проверить локально

Из папки проекта:

```powershell
npm ci
npm run check
npm test
npm run dev
```

Открыть http://127.0.0.1:3000. Начальная дата — 25.11.2026, маршрут — Светлогорск. Ключ VibeCode не нужен для работы демо.

## Собрать архив без сети

```powershell
npm run deploy:check
```

Результат — `deploy-preview.tar.gz`. Готовая копия текущей сборки — `yuktari-trip-planning-0.2.0.tar.gz`. Архив содержит только `src/`, `public/`, `package.json` и `package-lock.json`; `.env`, ключи, справочный PHP-комплект и локальные демо-записи не включаются.

В Windows то же действие доступно через `./deploy.ps1 -DryRun`; в Linux/macOS — `bash ./deploy.sh --dry-run`. Обе обёртки запускают единый скрипт `scripts/deploy.mjs`.

## Параметры для формы деплоя VibeCode

В карточке существующего сервера «Планирование выездов» откройте «Деплой» и используйте подготовленный архив с параметрами:

| Поле | Значение |
|---|---|
| Сервер | `d4cd0430-b066-441c-bfc7-62107a20b977` |
| Runtime | `node20`, согласно используемому примеру SyncPoint |
| Установка | `cd /opt/app && npm ci --omit=dev` |
| Запуск | `cd /opt/app && node src/server.js` |
| Порт | `3000` |
| `NODE_ENV` | `production` |
| `HOST` | `0.0.0.0` |
| `PORT` | `3000` |
| `B24_DOMAIN` | `yuktari.bitrix24.by` |

Ключ управления не нужен в среде работающего демо и не должен попадать в браузер. Названия полей формы могут отличаться; сверяйте параметры с актуальной карточкой деплоя платформы. Агент не выполнял этот шаг и не подтвердил совместимость runtime на целевом сервере.

Если выполняете доставку через терминал с восстановленным доступом к VibeCode, используйте `npm run deploy` или `./deploy.ps1` / `bash ./deploy.sh`. Команда заменяет код на целевом сервере; перед ней сохраните предыдущую рабочую версию. Пользователь выполняет реальную доставку самостоятельно.

## Проверить после выкладки

1. Открыть приложение через карточку сервера и проверить `/health` (через авторизованный шлюз, если доступ ограничен).
2. Проверить четыре экрана и сценарии из docs/DEMO.md.
3. Перезагрузить страницу — изменения демо должны сохраниться в этом браузере.
4. Убедиться, что запросы к реальным сделкам и Wialon не выполняются.

Для показа именно во вкладке сделки отдельно потребуется регистрация `CRM_DEAL_DETAIL_TAB`. Текущий архив сам приложение и место встраивания не регистрирует.

Для отката повторно доставить архив предыдущей проверенной версии. Демо-данные находятся в localStorage браузера и не являются общей серверной базой.
