# Ручная доставка версии 0.3

## Подготовка

```powershell
npm ci
npm run check
npm test
npm run deploy:check
```

Результат — deploy-preview.tar.gz; копия текущей сборки — yuktari-trip-planning-0.3.0.tar.gz. Внутри только src/, public/, package.json и package-lock.json. Ключи, .env, база, тестовые ответы API и PHP-шаблон не входят. Обёртки: ./deploy.ps1 -DryRun или bash ./deploy.sh --dry-run.

Для локального демо установить APP_MODE=demo и выполнить npm run dev. Для CRM использовать APP_MODE=bitrix и вход через VibeCode; настройки — [CRM.md](CRM.md).

## Параметры формы деплоя VibeCode

Выбрать существующий сервер d4cd0430-b066-441c-bfc7-62107a20b977. Пользователь выполняет реальную доставку самостоятельно.

| Параметр | Значение |
|---|---|
| Runtime | node20 |
| Установка | cd /opt/app && npm ci --omit=dev |
| Запуск | cd /opt/app && node src/server.js |
| Порт | 3000 |
| NODE_ENV | production |
| HOST | 0.0.0.0 |
| PORT | 3000 |
| B24_DOMAIN | yuktari.bitrix24.by |
| APP_MODE | bitrix |
| APP_URL | https://app-13fb2e983443.vibecode.bitrix24.tech |
| VIBE_APP_KEY | Секрет существующего OAuth-приложения |
| DATA_DIR | /opt/data/yuktari-trip-planning |
| dataDirs | ["/opt/data/yuktari-trip-planning"] |

VIBE_APP_KEY вносится в защищённую среду сервера, не в архив или frontend. VIBE_API_KEY работающему приложению не нужен. При доставке через npm run deploy разрешённые переменные передаются из локального .env, DATA_DIR и dataDirs устанавливаются скриптом. Не заменяйте каталог данных каталогом /opt/app: cleanDeploy очищает код. Сохраните предыдущий код и копию DATA_DIR перед обновлением. При развёртывании через форму отдельно проверьте сохранение переменных и права приложения на каталог данных.

Название и наличие полей в интерфейсе платформы могут отличаться; контракт отдельной VM и Galaxy различается. Скрипт предназначен для существующего BLACKHOLE-сервера, не создаёт новые ресурсы и не меняет его режим доступа.

1. Проверить журнал и /health через шлюз, открыть приложение из портала.
2. Проверить, что OAuth-приложению доступны crm, user, lists и placement. Авторизоваться как сотрудник.
3. Выполнить настройку групп, сотрудников и смен, затем привязать вкладку кнопкой администратора.
4. Провести приёмку на тестовой сделке по [CRM.md](CRM.md): подстановка, запись, перечитывание, права и одновременное бронирование.
5. Убедиться, что серверное хранилище переживает перезапуск и следующую доставку.
