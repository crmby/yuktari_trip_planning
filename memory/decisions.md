# Решения

## 25.11.2026 — VibeCode как целевая среда

Основание: пользователь прямо указал VibeCode и npm run deploy по образцу SyncPoint. Выбран Node.js-каркас с сохранением PHP-шаблона отдельно. Классический PHP OAuth/BX24 SDK не объявлен совместимым с VibeCode без адаптации.

## 25.11.2026 — границы первого этапа

Подготовлен только каркас и окружение. API портала отсутствует; маршруты /api/* закрыты ответом 503 до реализации авторизации. Нет выдуманных рабочих записей, регистрации приложений, платных ресурсов или изменения данных CRM.

## 25.11.2026 — доставка

Использован проверяемый список файлов; секреты, исходный PHP-комплект и материалы разработки не доставляются. Ключ управления не передаётся работающему приложению. Пример SyncPoint адаптирован без копирования его секретов и настроек сервера.

## 26.11.2026 — тестовая версия до восстановления сетевого доступа

Пользователь попросил сначала сделать тестовую версию и задеплоить её вручную; затем предоставил ТЗ и исключил работу с Wialon. Реализован демонстрационный интерфейс и логика на вымышленных данных без запросов к порталу. Это позволяет проверить сценарии независимо от сбоя TLS/сети и не требует передачи ключа в браузер.

Ограничение: localStorage не заменяет серверную базу и не гарантирует атомарное резервирование между сотрудниками. Продуктивные CRM-операции и регистрация вкладки допускаются только после серверной авторизации, утверждённой карты полей и алгоритма резервирования. Демо-правило: работа внутри окна и смены, шаг 30 минут, дорога 30 минут; позиция строки независима от резерва.

Исходные данные раннего демо мигрируются из schema 1 в schema 2 с сохранением записей и индивидуальных соответствий мастеров. Новая исходная демо-модель содержит явные группы маршрутов/типов клиентов; один мастер может входить в несколько групп.
