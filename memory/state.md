Добавлены создание/перенос/отмена/восстановление выездов, все товары тестовой сделки, фильтры, территории и координаты, отдельные позиция/окно/длительность, автоматическое назначение по группам и сменам, календарь месяца и конфликты. Демо хранится только в браузере; Wialon исключён пользователем и не затрагивается.

Проверено: 11 тестов Node.js и проверка синтаксиса; в браузере — создание/перенос/отмена, сохранение после перезагрузки, обычная неделя и исключения, конфликты, группы и новые мастера, фильтр города, ссылка на карту и контекст тестовой сделки. Ошибок в консоли браузера при проверке не обнаружено. Архив создаётся офлайн, без .env и справочного PHP-комплекта. Обёртки deploy.ps1 и deploy.sh добавлены для ручного запуска.

Реальные CRM-записи, авторизация сотрудника, атомарное серверное резервирование, общая база для нескольких менеджеров, геокодер и регистрация CRM_DEAL_DETAIL_TAB остаются отдельным этапом. Это не полная приёмка рабочего приложения по всем пунктам ТЗ. Ограничения и сценарии описаны в docs/DEMO.md; предварительная карта полей — docs/FIELD-MAP.md; ручная доставка — docs/MANUAL-DEPLOY.md.

## Обновление: версия 0.3, синхронизация CRM

По последующим требованиям пользователя реализован рабочий режим bitrix. Добавлены серверные модули проверки сессии через /me и /users/me, строгая проверка портала и прав, карта девяти пользовательских полей, routes из metadata инфоблока контакта с пагинацией, поиск сделок, загрузка календаря, все товарные позиции и телефон контакта. Контекст вкладки выбирает текущую сделку, отдельное приложение позволяет поиск.

Сохранение использует приватную файловую базу, атомарную замену и блокировку, проверку свежего снимка CRM и серверную проверку свободного времени. Резерв сохраняется до PATCH, результат сверяется чтением контакта и сделки. Неизвестный/частичный исход удерживает резерв и допускает проверку без повторной записи. Незавершённая операция восстанавливается после перезагрузки страницы. Отмена очищает дату/окно, не меняет товары, стадии или Wialon.

Мастера выбираются из сотрудников, ФИО подтверждается сервером; хранятся ID, активность, направления из общего справочника, группы, Wialon ID только как значение, недельные смены и исключения. Из формы выезда убраны дополнительные территориальные поля, координаты, ручной статус и особая отметка; кнопка «Новая запись» в разделе записи убрана. Добавлены квартира, телефон и требуемые колонки листа, отдельные окно и комментарий.

Пользователь подтвердил наличие OAuth-приложения и обещал добавить VIBE_APP_KEY в .env. Значения .env не читались и не выводились. Реальные CRM-вызовы, привязка вкладки и деплой не выполнялись. Настройка сервера и приёмка описаны в docs/CRM.md и docs/MANUAL-DEPLOY.md. Скрипт доставки передаёт серверный OAuth-ключ и объявляет постоянный каталог /opt/data/yuktari-trip-planning через dataDirs; management key не передаётся в runtime.

Проверено: 21 тест Node.js (в том числе конкуренция, устаревшая CRM, частичная запись, потерянный ответ, права, идемпотентность и карта полей). В браузере с тестовым API выполнены поиск сделки, подстановка, сохранение, лист с квартирой/телефоном/всеми услугами и контекст сделки с заблокированным выбором; ошибок консоли не обнаружено. Это не подтверждает работу на реальном портале. Ограничения: один сервер/файловая база; прямые изменения CRM не переносят серверное назначение автоматически; реальный тип инфоблока и права нужно проверить. Wialon остаётся исключён.

## Исправление сообщений авторизации, 26.11.2026

Пользователь сообщил «Сессия Битрикс24 истекла» при открытии внутри Битрикс24. Обнаружена ошибка диагностики: клиент превращал любой HTTP 401 VibeCode в утверждение об истёкшей сессии. Теперь различаются недействительный/отозванный/истёкший ключ, несовпадение OAuth-приложения, отсутствие сессии/первого доступа; показываются безопасный код и этап /me, /users/me или CRM без исходного ответа и секретов. Отказы Gateway до приложения также получают понятное сообщение. Для активных форм добавлен лёгкий запрос /api/runtime раз в четыре минуты; заголовки не подделываются, авторизация не ослаблена.

Проверены npm run check, npm test (22 теста), npm run deploy:check. Архив 0.3.0 пересобран. Реальную причину отказа конкретной сессии установить пока нельзя: старое сообщение скрывало код, доступа к действующей серверной сессии нет. Требуется свежий вход из меню портала; если не помогает — ручная доставка исправленной сборки и безопасный код ошибки. .env не просматривался, реальный деплой/CRM/ключи/режим доступа не менялись.
