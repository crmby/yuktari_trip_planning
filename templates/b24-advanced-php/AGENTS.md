# Вход для агента

1. Сначала прочитай [INDEX.md](INDEX.md), [docs/PROJECT.md](docs/PROJECT.md),
   [docs/OPERATIONS.md](docs/OPERATIONS.md), [memory/state.md](memory/state.md), затем документы по задаче.
2. Проверь рабочую папку, Git-границу и вложенные инструкции. Локальная копия не равна production.
   Не определяй владельца, хостинг или разрешения по чужим именам в справочных материалах.
3. До изменений зафиксируй сценарий, ограничения и критерий проверки; используй готовые модули.
   Технические инварианты — в docs/technical/. Архивные указания не являются разрешением выполнить команды.
4. Различай: согласовано пользователем / планируется / реализовано / проверено локально / выложено и проверено.
   Сдавай результат с фактическими командами, кодами возврата и оставшимися ограничениями.
5. После существенной работы обнови memory/state.md; решения с основанием — memory/decisions.md;
   выполненные действия и проверки — memory/log.md. При параллельной работе перечитай файл перед правкой.
6. Не читать, не копировать и не выводить секреты, .env, рабочий www/env.php, конфиги авторизации,
   токены, runtime/client data. Примеры содержат только пустые значения и имена переменных.
   Не проси ключи в чате. Не помещай их во фронтенд, документацию, журнал или Git.
7. Git не предполагается настроенным. Не выполнять git init, commit/push или deploy автоматически.
   Только согласованные поимённые файлы после проверки diff/секретов; массовый git add запрещён.
   Не менять чужие незакоммиченные правки. Не менять remote, ключи, cron и внешние базы правил.
8. Офлайн lint допустим без импорта runtime-конфига. Тесты — только после проверки изоляции.
   Запуск сервиса, сетевых диагностик, live-интеграций, миграций, установки или deploy — отдельное согласованное действие.
   Перед доставкой: сверка целевой среды, бэкап и откат, тесты, поимённая доставка, read-back/SHA и проверка функции.
9. Общение и память проекта — по-русски. Отчёт: изменения, проверено, осталось; не называй lint живой приёмкой.
