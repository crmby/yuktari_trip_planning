# Поток установки

> ⚠ Первая установка принимается ТОЛЬКО по криптодоказательству: присланный
> `REFRESH_ID` обменивается на токены нашим `client_secret` (`verifyAndAdopt`),
> домен и `member_id` берутся из ответа oauth, а не из POST. Не подтвердилось —
> 403 «Установка не подтверждена порталом». Разовый обход для коробочного
> портала со своим сервером авторизации — `UNVERIFIED_FIRST_INSTALL` (разовый билет: домен +
> секрет от 32 знаков + срок) в `env.php`. Возвращать ничего обратно не нужно: билет СГОРАЕТ
> после первого применения — это уже не выключатель, который можно забыть выключить. Домен
> берётся и из `DOMAIN`, и из `SERVER_ENDPOINT`: коробка поля `DOMAIN` не присылает вовсе, и
> пока билет читал только его, единственный обход для коробки отказывал именно на коробке.
>
> Async `ONAPPINSTALL` не несёт generation или порядкового номера. Поэтому он
> может только одноразово заполнить **пустой** `application_token`, если его
> `member_id` и оба OAuth-токена точно совпали с уже сохранённым browser-flow под
> CAS. OAuth, generation и `confirmed` событие не меняет; непустой ключ не
> ротирует. Дубликат с тем же ключом — no-op, другой ключ — 403 без журнала.
> Завершение установки по-прежнему подтверждает только `app.info=true`.


Шаблон делает двухфазный install (см. актуальный KB
b24-oauth-install (`[внешний ресурс исходного контура]`, внешняя/исходная ссылка; не входит в комплект)).
Эта диаграмма — что когда происходит, чтобы при дебаге понимать «на каком POST'е сейчас».

## Полный сценарий: чистая установка на новом портале

```
┌──────────────────┐                    ┌──────────────────────┐
│ Админ в Б24      │                    │ Наш сервер           │
│ нажимает         │                    │ index.php            │
│ «Установить»     │                    │                      │
└────────┬─────────┘                    └──────────┬───────────┘
         │                                         │
         │   POST /  (AUTH_ID, REFRESH_ID,         │
         │            REFRESH_ID, SERVER_ENDPOINT, │
         │            member_id; INSTALL /         │
         │            APPLICATION_TOKEN / DOMAIN*) │
         ├────────────────────────────────────────►│
         │                                         │
         │                                         │ 1. verifyAndAdopt()
         │                                         │    - REFRESH_ID меняем на токены НАШИМ секретом
         │                                         │    - домен и портал берём из ответа oauth
         │                                         │      (из POST и REFERER их НЕ берём: подделываются)
         │                                         │    - не подтвердилось → 403, состояние не создаётся
         │                                         │
         │                                         │ 2. resolveUserContextFromAuth()
         │                                         │    user.current + user.admin по AUTH_ID
         │                                         │
         │                                         │ 3. portal-admin подтверждён; сначала
         │                                         │    bind + read-back всех placements
         │                                         │ 4. атомарно ставится requested поколения
         │                                         │
         │                                         │ 5. renderInstallFinishPage()
         │                                         │    HTML с BX24.installFinish() + reload 700ms
         │  ◄──────────────────────────────────────┤
         │                                         │
         │   BX24.installFinish()                  │
         │   Б24 переключает INSTALLED:false→true  │
         │                                         │
         │   После 700ms: location.reload()        │
         │                                         │
         │   POST /  (AUTH_ID, ...)  — open #2     │
         ├────────────────────────────────────────►│
         │                                         │
         │                                         │ 1. verifyAndAdopt()
         │                                         │    !isFirst, !isFormal → skip
         │                                         │    (admin-токен остаётся)
         │                                         │
         │                                         │ 2. transport-fence + user-context admin
         │                                         │
         │                                         │ 3. app.info single-flight (5с): true
         │                                         │    атомарно ставит confirmed поколения;
         │                                         │    false после requested = неизвестный исход,
         │                                         │    автоматического повтора НЕТ
         │                                         │
         │                                         │ 4. session gate → admin OK
         │                                         │
         │                                         │ 5. render template.html
         │  ◄──────────────────────────────────────┤
         │                                         │
         │   Видит UI приложения                   │
```

\* `DOMAIN` на cloud приходит не всегда — и это не важно: на ПЕРВОЙ установке домен и портал
берутся из ответа сервера авторизации, а не из присланного POST. Резолв из POST/REFERER остался
только на пути `saveTokensFromInstall()` (обходной режим для коробки со своим OAuth-сервером).

## Открытие не-админом

```
┌──────────────────┐                    ┌──────────────────────┐
│ Не-админ в Б24   │                    │ index.php            │
│ открывает app    │                    │                      │
└────────┬─────────┘                    └──────────┬───────────┘
         │                                         │
         │   POST /  (AUTH_ID юзера, не админа)    │
         ├────────────────────────────────────────►│
         │                                         │
         │                                         │ 1. запись токенов НЕ делается
         │                                         │    (не первая установка и нет доказанной
         │                                         │     смены установки — токен установщика цел)
         │                                         │
         │                                         │ 2. не-админ не трогает installFinish-маркер
         │                                         │    и не вызывает app.info
         │                                         │
         │                                         │ 3. гейт доступа: кто открыл?
         │                                         │    user.current + user.admin по ЕГО токену
         │                                         │    владелец / в списке / админ портала → сессия
         │                                         │    иначе → 403 "Нет доступа"
         │                                         │    портал не ответил → 503 "не отвечает"
         │  ◄──────────────────────────────────────┤
         │                                         │
```

KB: `b24-local-app-tokens-save-only-on-install` (grep по общему INDEX.md (`[внешний ресурс исходного контура]`, внешняя/исходная ссылка; не входит в комплект)) —
**критично не сохранять токены этого юзера**: приложение ходит в портал под токеном
установщика (фабрика `b24()`), и если его затереть токеном обычного сотрудника, то серверные
вызовы — фоновая работа, привязка плейсментов, справочники — начнут получать ACCESS_DENIED.
Никакого `proxy.php` в шаблоне нет и не было: это остаток описания от другого приложения.

## Reinstall в Developer-карточке

Кейс: админ delete'нул local-app, потом recreate'нул в той же карточке (или просто «Переустановить»).

```
B24 может прислать POST / без INSTALL и APPLICATION_TOKEN (тот же member_id)
                                         │
                                         │ verifyAndAdopt()
                                         │ app.info=false + текущий portal-admin + OAuth proof
                                         │ → новая OAuth-пара и текущее поколение установки
                                         │
                                         │ Новое поколение не наследует глобальный маркер
                                         │ installFinish от прошлой установки
                                         │   → не-админы упрутся в «приложение не установлено»
                                         │
                                         │ placements обязаны пройти bind/read-back до finish.
                                         │ После requested неизвестный исход блокирует
                                         │ автоповтор; восстановление только после ручной проверки
```

**Обработчик установки ОДИН — `www/index.php`.** Подлинность install-POST проверяется одной
функцией на всех публичных входах —
`installPostAuthenticity()` в `www/api/b24.php`: строгая сверка `application_token`, а для
старой установки без него — разовое доверие, но только после transport-fence и подтверждения
админа того же портала, не чаще
раза в 10 секунд. Дозапись `application_token` идёт под тем же условием: без него посторонний
подсаживал свой токен и следующим запросом проходил проверку как свой (ревью 29.07.2026).
KB: `rule-b24-verify-application-token` (grep по общему INDEX.md (`[внешний ресурс исходного контура]`, внешняя/исходная ссылка; не входит в комплект)),
`b24-local-app-app-reinstall-application-token-mismatch` (grep по общему INDEX.md (`[внешний ресурс исходного контура]`, внешняя/исходная ссылка; не входит в комплект)).
